# Write the first useful message

Read the user's offer and ICP in `company/private/`, evidence for the selected person/company, `context/identity/proof.md` and the actual voice samples. The example files are synthetic.

Lock five facts before drafting: buyer/remit, observed situation, useful offer, cleared proof (or none), language/register. Missing proof is a reason to omit the claim, not invent a customer or outcome.

Write one specific observation, its connection to the buyer's work and one concrete ask. Phrase uncertain inferences as questions; do not present an inferred problem as a known fact. A relevant resource can be the offer itself. No calendar or resource URL is usable until it actually exists.

Match the author's rhythm and sign-off from samples. Use short paragraphs, concrete nouns and one ask. Cut generic flattery and sentences that could describe every recipient. Follow-ups add a new useful detail. Mention a prior touch only when its actual delivery or conversation supports that claim.

For an experiment, read `split-test-designer` and vary only its declared dimension. For generated copy, use [the prompt](../../../prompts/generate_first_touch.md) and its input/output contract; do not paste an entire private swipe corpus into a public template.

Return subject, body, source-backed rationale, unresolved claims and variant metadata. Check every merge variable in a rendered sample. Respect the user's channel posture and sender identity requirements. Drafting does not send; use `prepare_sequence` and the enrollment skill for the final handoff.
